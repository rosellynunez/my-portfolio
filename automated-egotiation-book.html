Design System for Academic Book

Hero Image - Project Overview

Project Overview

Introduction to Automated Negotiation” is an academic ebook by Dr. Dave de Jonge. I designed and developed the website with a focus on clarity, accessibility, and long-term scalability. Although it currently functions as a single-page site, the structure and components were built as a flexible foundation for future chapters and interactive features.

  • Works perfectly across all devices, even though the webpage is mainly for desktop (students need to download and work with the framework)
  • Can scale efficiently as the book expands with new chapters and interactive features

project goals

  • Present academic content in a clear and structured way.
  • Offer an intuitive downloading experience for students and researchers.
  • Build a scalable design system using semantic tokens and reusable components.
  • Ensure WCAG AA accessibility through colour contrast, keyboard support, and semantic HTML.
  • Create a responsive interface that works well across devices and keeps a clean visual hierarchy.
  • Add subtle micro-interactions to improve usability without distracting from scholarly content.

mi role

As the UI Designer, Design System Architect, and Frontend Developer, I led the project end-to-end. My responsibilities included:

  • Defining the visual language.
  • Creating the token-based design system,
  • Building reusable components
  • Implementing responsive layouts,
  • Ensuring accessibility compliance.
  • Translating static concepts into living, interactive experiences

1. UX Approach

Before moving into the visual design, I spent time understanding user needs through conversations with the author and students. Insights revealed that users needed quick access to the latest book version for frequent downloads, along with clear version history to track updates.

I also learned that researchers often need to cite the book immediately, so providing the BibTeX entry in a clear and accessible way was a key requirement.

Because these users may work on different devices—sometimes reading from mobile, but often downloading materials from desktop—it was important to design an interface that adapts across screen sizes.

With these insights in mind, I made some key decisions:

  • The primary CTA (“Download v0.2”) is placed directly in the hero section so returning visitors can access it instantly.
  • The “Book Versions” section uses a structured table on desktop, and transforms into stacked cards on mobile to support easier scanning.
  • I added ARIA labels, clear keyboard focus states, and a live status message for the copy-to-clipboard interaction, making the experience reliable for screen reader users.
  • The overall layout follows a consistent vertical rhythm and spacing scale to help users understand each section at a glance.

2. UI Design & Visual Language

The visual direction needed to feel academic, modern, and easy to read. To achieve this, I created a clean interface where colours, typography, and spacing work together to support readability and trust.

Colour system

I established a two-tone colour strategy that separates structure from interaction:

  • Primary (blue): structure, titles, and base text
  • Secondary (teal): interactive elements such as buttons, links, focus rings

This contrast helps users immediately distinguish content from actions while maintaining a consistent academic tone.

Typography

I chose two complementary typefaces:

  • Plus Jakarta Sans for headings (clarity and modern tone).
  • Lato for paragraphs (high readability).

A clear typographic scale supports hierarchy and consistency across sections.

3. Design Systems Foundations

Beyond the visual decisions, I developed a lightweight design system that gives the site long-term scalability. Even though this phase of the project is a single page, the design system lays the foundation for future chapters, downloadable resources, and potential interactive tools.

Semantic design tokens

I built a token structure to ensure consistency and simplify future updates

  • Colour tokens: roles for text, surfaces, interactive states
  • Surfaces: hover, focus, active states
  • Typography: base, interactive, button text, sizes, weights, and hierarchy
  • Borders: separator and interactive widths
  • Spacing scale: applied across sections and cards
  • Interactive surfaces: unified hover, focus, and active states

By naming tokens semantically (e.g., --surface-link-interaction, --border-width-interactive), I ensured that the design scales while staying easy to maintain.

Component architecture

Each component was built as a reusable module:

  • Buttons share the same focus states, and interaction rules
  • Cards follow a consistent internal structure
  • Tables adapt to mobile through a token-based responsive system
  • The navigation is fully keyboard-accessible and screen-reader friendly

This modular approach ensures consistency and simplifies future updates.

Scalability

This foundation allows the author to add new book versions without redesigning the page, integrate future interactive tools, maintain visual consistency across new pages and evolve the site while keeping accessibility at the core.

The design system ensures that the project can grow in a structured way, rather than becoming a collection of disconnected screens.

4. Accessibility

Since the target audience includes students and researchers working in academic environments, the website needed to be usable by everyone — including people using screen readers, keyboard navigation, or high-contrast settings.

Semantic structure

I built the entire page using meaningful HTML elements such as <nav>, <header>, <section>, <table>, and <footer>. Clear section titles and consistent hierarchy help both users and assistive technologies understand the structure of the content.

Keyboard Navigation & Focus States

Every interactive element — links, buttons, the mobile navigation menu, and the copy-to-clipboard component — is fully operable with a keyboard.

I implemented visible focus rings using semantic design tokens to ensure users always know where they are on the page. Hover and focus states share the same interactive surface, but focus adds an accessible outline for clarity.

Screen Reader Labels & ARIA

To improve the experience for users relying on screen readers, I added:

  • Descriptive ARIA labels for buttons such as “Open menu”, “Close menu”, and “Copy BibTeX entry”.
  • Additional labels for the mobile version table, where each row becomes a card.

These enhancements make sure that all content is communicated clearly, even when the layout changes.

Colour contrast

All colour combinations follow WCAG AA standards. I used tokens for text, surfaces, and interactive elements to maintain predictable contrast across the interface.

The teal secondary colour was chosen specifically because it provides accessible contrast on both light and dark surfaces.

Responsive Behaviour with Accessibility in Mind

The version table transforms into accessible cards on mobile. Each card includes descriptive labels, ensuring the information hierarchy remains intact regardless of the layout.

  • Hero layout adapts with repositioned text for readability
  • Cards become a grid or single column depending on width
  • The version table transforms into stacked cards, each row becoming a readable block
  • Navigation becomes a hamburger menu with accessible toggling

5. Responsive Web Layout

While the site is designed primarily for desktop use as a practical book resource, I implemented a comprehensive responsive strategy:

  • Hero sections adapt with repositioned text for optimal readability on all devices
  • Content cards transform into a flexible grid or single column based on viewport width
  • The version table becomes stacked cards, converting each row into readable blocks on smaller screens
  • Navigation condenses into an accessible hamburger menu with smooth toggling
  • This ensures the website remains functional and accessible across all devices when needed

6. Interaction design

Small micro-interactions support usability:

  • Buttons lift slightly on hover
  • Smooth transitions for the navigation menu
  • Copy button turns into a checkmark on success
  • Surfaces use subtle transparency via color-mix() for softer UI feedback

These interactions stay subtle to avoid overwhelming the academic tone of the site.

7. Outcome

The final result is a clean, structured, and accessible website that effectively serves both students and researchers. The design is built on a solid system foundation, allowing the site to grow alongside the book's content, while intentional UI and UX choices ensure navigation is simple and clear.

Technically, the structure is crafted with semantic HTML, custom CSS, and minimal vanilla JavaScript. We deliberately avoided heavy frameworks to guarantee fast load times. Furthermore, the consistent use of design tokens for all spacing, colors, and typography reduces CSS duplication and makes the codebase easy to maintain.

This project was more than a single-page website; it was about creating a clear, trustworthy, and scalable platform for an evolving academic resource. Through thoughtful UX, a strong visual system, and accessible coding practices, the site is now equipped to support both immediate needs and future expansion. It showcases my ability to design cohesive interfaces, structure information effectively, and build flexible, long-lasting design systems.
